# Fleetroll 0.3.0

Released November 4, 2026. This release includes changes since the 0.2.4 version
boundary, with a clearer CLI, safer host operations, and expanded fleet and
rollout reporting.

## CLI and override workflow

- Commands are organized into resource groups: `host`, `override`, `vault`,
  `note`, `gather`, `fleet`, `rollout`, `data`, and `debug`. Use commands such as
  `fleetroll override set`, `fleetroll host monitor`, and `fleetroll gather all`.
  Existing flat names such as `host-set-override` and `gather-host` remain hidden
  compatibility aliases. The legacy `gather HOST_OR_FILE` form also works.
- `fr` is available as a shortcut for `fleetroll`.
- `override create` generates overrides from a branch, PR number, or GitHub PR
  URL. It resolves fork repositories, verifies the exact branch before writing,
  and refuses to overwrite files. Output defaults to the current directory,
  with `--output` and `--output-dir` options. `tools/create_override.sh` remains
  a wrapper defaulting to the repository's `configs/overrides` directory.
- Generated overrides include worker-type guidance and an empty, commented
  `WORKER_TYPE_OVERRIDE` assignment instead of a hardcoded staging pool.
- `gather host` accepts multiple hostnames in one invocation.

## Host operation safeguards

- `override set` checks an override's worker type against each target host's
  latest successful recorded role. It accepts the base worker type or that
  type followed by a hyphen and a nonempty suffix. Mismatches and unknown roles
  block the whole deployment before writes. Previews display observation
  timestamps; operators remain responsible for deciding when to refresh them.
  Use `--allow-worker-type-mismatch` for intentional exceptions. This check
  also applies with `--force` and `--no-validate`.
- Override and vault writes, and override removal, automatically refresh host
  observations unless `--no-audit` is supplied.
- `host run-puppet` requires `--confirm`, including for single-host runs. It
  defaults to verified single-attempt execution, reports batch progress, and
  records transport failures. PTY sizing fixes improve terminal output.
- `host reboot-if-idle` provides an operator-triggered Linux reboot request
  after checking live worker state. It requires `--confirm` and requests a
  reboot only when the reported state is `IDLE`.

## Fleet visibility and rollout reports

- `fleet status` summarizes override coverage by Puppet role or worker type.
- `rollout report` compares recent outcomes on verified master and each
  override, retains compact configuration history, reports cohort health
  independently, and separates attribution gaps from observed task outcomes.
  Reports support partial coverage and scope historical evidence to the
  selected role or pool.
- Fleet and rollout reports show current approximate queue counts. Bare worker
  type selectors default to the `releng-hardware` provisioner.
- Taskcluster collection uses REST and observed worker identities, including
  overridden pools, rather than relying only on a role whitelist.
- `data freshness` reports host and Taskcluster observation age and supports
  freshness requirements for automation.
- The monitor adds Puppet success visibility, stale-data indication, persistent
  filter history, a named-filter picker, and OS sorting.
- The read-only web interface provides a host grid with filter and sort parity,
  a monitor-style header, and saved and recent filter selection.

## Release notes and upgrading

Release notes now use release boundaries: a version's notes cover changes after
the previous version bump through its own bump. Later commits appear in a
separate `unreleased.md` draft. `--rolling-main` remains available for the legacy
era interpretation. The convenience script no longer forces regeneration of all
historical drafts. See the [release workflow](README.md).

Existing flat CLI names remain supported. New automation should use the resource
groups. Review override-deployment scripts for the new worker-type check and
Puppet-run scripts for the explicit confirmation requirement. Within `gather`,
`all`, `host`, `tc`, and `gh` are reserved action names; use a path such as
`./host` for an ambiguously named host-list file, or a FQDN for a hostname.
